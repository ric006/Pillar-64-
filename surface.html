Pillar 64 on Surface

Microsoft Surface tablets need a special Linux kernel for the touchscreen and pen. Pillar does not include it yet, but you can add it in about fifteen minutes.

What has been tested

Pillar 64 1.0 was installed on a Surface Pro 7. On that machine the Surface kernel installed and started, and the Secure Boot key steps below worked. Other Surface models may work too, but they have not been tested with Pillar.

The Surface kernel and the touch service come from the community linux-surface project. Pillar does not maintain them.

Before you start

  • Pillar 64 is installed on the Surface and the computer is connected to the internet.
  • You will paste commands into a terminal. Each box below has a Copy button.
  • If the installer would not start on your Surface, you may have had to turn Secure Boot off. That is fine. Install first, and use the Secure Boot section at the end only if you want it back on.

Install the Surface kernel and touch support

  1. Add the Surface package key

    wget -qO - https://raw.githubusercontent.com/linux-surface/linux-surface/master/pkg/keys/surface.asc | gpg --dearmor | sudo dd of=/etc/apt/trusted.gpg.d/linux-surface.gpg

  2. Add the Surface package source

    echo "deb [arch=amd64] https://pkg.surfacelinux.com/debian release main" | sudo tee /etc/apt/sources.list.d/linux-surface.list

  3. Update the package list

    sudo apt update

  4. Install the kernel and the touch service

    sudo apt install linux-image-surface linux-headers-surface iptsd

    Do not add libwacom-surface to this command. The linux-surface guide says it has a known bug on Ubuntu 26.04 that can remove desktop packages.

  5. Update the boot menu, then restart

    sudo update-grub

    After the restart, check that you are on the Surface kernel:

    uname -r

    The line it prints should contain the word surface.

Touch gestures such as scrolling and pinching work best in a Wayland session, which is what Pillar uses by default.

Secure Boot (optional)

The Surface kernel is not signed by Ubuntu. If Secure Boot is on, the computer refuses to start it and shows bad shim signature. To use Secure Boot with it, enroll the Surface key once. You can do the first step with Secure Boot still off.

  1. Queue the key

    sudo apt install linux-surface-secureboot-mok

  2. Shut down completely

    Do not restart. Turn the Surface off.

  3. Turn Secure Boot on

    Hold Volume Up, press and release Power, and keep holding Volume Up until the UEFI menu opens. Go to Security, then Secure Boot, then Change configuration. Choose Microsoft & 3rd Party CA and save.

    If Windows is still installed on this Surface with BitLocker, have its recovery key ready first. Changing this setting can lock Windows until you enter it.

  4. Enroll the key

    When the Surface starts, a blue MokManager screen appears. Choose Enroll MOK, then Continue, then Yes. When it asks for a password, type surface. This screen uses a QWERTY keyboard layout. Then choose Reboot.

  5. Check that it worked

    sudo mokutil --sb-state

    It should say SecureBoot enabled, and uname -r should still show the surface kernel.

If something goes wrong

It says "bad shim signature" at start-up
Secure Boot is on but the Surface key is not enrolled yet. At the boot menu choose Advanced options and pick the kernel without surface in its name, such as 7.0.0-30-generic. Then repeat the Secure Boot steps. If the blue screen did not appear, run sudo apt remove linux-surface-secureboot-mok, install it again, and repeat from step 2.
Pillar does not start at all
Open the UEFI menu (Volume Up + Power) and set Secure Boot to Disabled. Pillar starts normally with it off.
The integrity check lists new files
Installing a kernel changes system files, so the Pillar system integrity check may list them at the next start. That is expected.

Going back to the standard kernel

Start Pillar on the standard kernel first (Advanced options at the boot menu, then the generic one). Then remove the Surface packages and the Surface package source:

sudo apt remove linux-image-surface linux-headers-surface iptsd
sudo rm /etc/apt/sources.list.d/linux-surface.list

Then run sudo update-grub and restart.
